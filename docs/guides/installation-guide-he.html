1. סקירה – איך המערכת בנויה

טיפולוג היא אפליקציית ווב הרצה על המחשב שלכם. אין צורך בשרת חיצוני, בשירות ענן או בבסיס נתונים נפרד:

  • המערכת בנויה על Next.js (סביבת Node.js) ורצה כתהליך אחד במחשב.
  • כל הנתונים נשמרים בקובץ SQLite יחיד: data/tipulog.db בתוך תיקיית הפרויקט. הקובץ נוצר אוטומטית בהפעלה הראשונה.
  • הגישה למערכת היא דרך הדפדפן, בכתובת http://localhost:3000.
המשמעות: בהתקנה מקומית הנתונים הרפואיים נשארים אצלכם במחשב בלבד, וגיבוי = העתקת קובץ אחד (פרק 7). רוצים גישה מכל מקום ובוט וואטסאפ אמיתי? חלק ב׳ (פרקים 9–13) מסביר איך לפרוס את המערכת כאתר אינטרנט.

4. התקנה והפעלה ראשונה

כל הפקודות מורצות מתוך תיקיית הפרויקט.

שלב 1 – התקנת התלויות

npm install

ההתקנה אורכת דקה-שתיים ומורידה את כל הספריות הנדרשות לתיקיית node_modules.

שלב 2 (לא חובה) – נתוני הדגמה

כדי להתרשם מהמערכת עם נתונים לדוגמה (מטפלת דמו, 10 מטופלים, פגישות, סיכומים ותשלומים):

פרטי הכניסה שנוצרים:

לשימוש אמיתי: דלגו על שלב זה והירשמו עם חשבון משלכם במסך ההרשמה. אם כבר הרצתם את נתוני הדגמה ותרצו להתחיל נקי – ראו "איפוס המערכת" בפרק 8.

שלב 3 – הפעלה

כשמופיעה השורה Ready, פתחו דפדפן בכתובת:

http://localhost:3000

תועברו למסך ההתחברות. היכנסו עם משתמש הדמו או לחצו הרשמה ליצירת חשבון חדש.

עצירת המערכת: חזרו לחלון הטרמינל ולחצו Ctrl+C.

5. הפעלה שוטפת (מצב ייצור)

לעבודה יומיומית מומלץ להריץ במצב ייצור (production) – מהיר ויציב יותר ממצב הפיתוח:

npm run build
npm start

המערכת תהיה זמינה באותה כתובת: http://localhost:3000. יש להריץ npm run build מחדש רק לאחר עדכון גרסה של הקוד.

הפעלה אוטומטית עם המחשב (רשות)

אפשר להגדיר שהמערכת תעלה אוטומטית: ב-Windows דרך Task Scheduler, ב-macOS דרך launchd, וב-Linux דרך שירות systemd. לחלופין, כלי כמו pm2:

npm install -g pm2
pm2 start npm --name tipulog -- start
pm2 save

6. הגדרות מתקדמות

ההגדרות נקבעות באמצעות משתני סביבה (אפשר בקובץ .env בתיקיית הפרויקט):

משתנהברירת מחדלתפקיד
SESSION_SECRETמפתח פיתוח מובנהמפתח חתימת ההתחברות. חובה להגדיר ערך אקראי ארוך משלכם בשימוש אמיתי.
DATABASE_FILE./data/tipulog.dbמיקום קובץ הנתונים. אפשר להפנות לתיקייה מגובה (למשל תיקיית ענן מסונכרנת).
UPLOADS_DIR./data/uploadsתיקיית המסמכים המקומית (לשונית "מסמכים" בתיק המטופל).
STORAGE_DRIVERlocalהגדירו s3 לשמירת מסמכים באחסון ענן תואם S3.
TWILIO_AUTH_TOKEN–אימות חתימה של הודעות וואטסאפ נכנסות (Twilio).

אחסון מסמכים בענן (S3 / R2)

כברירת מחדל מסמכים נשמרים מקומית. לשמירה בענן הגדירו ספק אחסון תואם S3 – למשל Amazon S3, Cloudflare R2, Backblaze B2 או MinIO:

STORAGE_DRIVER=s3
S3_BUCKET=tipulog-documents
S3_REGION=auto
S3_ACCESS_KEY_ID=xxxxxxxx
S3_SECRET_ACCESS_KEY=xxxxxxxx
# רק לספקים שאינם AWS (למשל Cloudflare R2):
S3_ENDPOINT=https://<account-id>.r2.cloudflarestorage.com

מסמכים שהועלו לפני המעבר לענן יישארו זמינים מהאחסון המקומי; חדשים יישמרו בענן.

חיבורי וואטסאפ (Twilio)

הבוט לקביעת תורים והתזכורות פועלים מיידית במצב סימולציה, ללא שום חיבור חיצוני. לחיבור וואטסאפ אמיתי – קבלת הודעות מהמטופלים ושליחת תזכורות – ראו את המדריך המלא בפרק 13.

דוגמה לקובץ .env:

SESSION_SECRET=replace-with-a-long-random-string
DATABASE_FILE=./data/tipulog.db

יצירת מחרוזת אקראית למפתח:

node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

שינוי פורט

npm start -- -p 4000
אבטחה: המערכת מיועדת להרצה מקומית. אל תחשפו אותה לאינטרנט ללא HTTPS, חומת אש והקשחה מתאימה – מדובר במידע רפואי רגיש.

7. גיבוי ושחזור נתונים

גיבוי

  1. עצרו את המערכת (Ctrl+C) או ודאו שאינה באמצע פעולה.
  2. העתיקו את קובץ data/tipulog.db למקום בטוח (דיסק חיצוני / ענן).
# דוגמה (macOS / Linux)
cp data/tipulog.db ~/backups/tipulog-$(date +%F).db
מומלץ: גיבוי יומי אוטומטי – משימה מתוזמנת שמעתיקה את הקובץ עם תאריך בשם.

שחזור

  1. עצרו את המערכת.
  2. החליפו את data/tipulog.db בקובץ הגיבוי (באותו שם).
  3. הפעילו מחדש – כל הנתונים יחזרו למצב הגיבוי.

מעבר למחשב חדש

התקינו את המערכת במחשב החדש (פרקים 2–4, ללא נתוני דגמה) והעתיקו אליו את קובץ הנתונים – זה הכול.

‏איפוס המערכת (מחיקת כל הנתונים)

אזהרה: פעולה בלתי הפיכה – כל המטופלים, הפגישות והתשלומים יימחקו. גבו קודם!

9. בחירת דרך הפריסה

כדי שהמערכת תהיה זמינה כאתר אינטרנט – מכל מחשב ונייד, וגם כדי ש-Twilio יוכל לשלוח אליה הודעות וואטסאפ – יש לפרוס אותה על שרת עם כתובת ציבורית. חשוב להבין אילוץ אחד:

אילוץ מרכזי: המערכת שומרת את הנתונים בקובץ SQLite ואת המסמכים בתיקייה מקומית. לכן היא צריכה שרת עם דיסק קבוע ותהליך רץ. פלטפורמות Serverless כמו Vercel אינן נתמכות כפי שהמערכת בנויה היום (הדיסק שלהן נמחק בכל בקשה).
דרךלמי מתאימהעלות אופיינית
שרת VPS (פרק 10)שליטה מלאה, ביצועים, מחיר קבוע. הדרך המומלצת לקליניקה.‎5–12$ לחודש (Hetzner / DigitalOcean / Lightsail)
Docker (פרק 11)מי שכבר מריץ שרת עם Docker, או NAS ביתי.לפי השרת הקיים

בכל הדרכים חובה: דומיין (או תת-דומיין) שמפנה לשרת, ו-HTTPS. מדובר במידע רפואי – אל תפעילו את המערכת על HTTP גלוי.

10. פריסה על שרת VPS – מדריך מלא (מומלץ)

הדוגמאות עבור Ubuntu 24.04. השלבים זהים בכל ספק ענן (Hetzner, DigitalOcean, AWS Lightsail, Linode).

שלב 1 – שרת ודומיין

  1. צרו שרת (Droplet/Instance) עם Ubuntu, ‏1GB זיכרון ומעלה, ורשמו את כתובת ה-IP שלו.
  2. אצל רשם הדומיין שלכם צרו רשומת A שמפנה את הדומיין (למשל clinic.example.co.il) לכתובת ה-IP.
  3. התחברו לשרת: ssh root@YOUR-IP

שלב 2 – התקנת Node והמערכת

apt update && apt upgrade -y
curl -fsSL https://deb.nodesource.com/setup_22.x | bash -
apt install -y nodejs git nginx
git clone https://github.com/effimorremitrix/tipulog-.git /opt/tipulog
cd /opt/tipulog
npm ci
npm run build

שלב 3 – משתני סביבה והרצה כשירות (pm2)

cd /opt/tipulog
cat > .env << 'EOF'
SESSION_SECRET=PASTE-A-LONG-RANDOM-STRING-HERE
EOF
npm install -g pm2
pm2 start npm --name tipulog -- start
pm2 startup   # מדפיס פקודה – הריצו אותה כדי שהשירות יעלה אחרי ריסטרט
pm2 save

יצירת מחרוזת אקראית: node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

שלב 4 – Nginx כ-Reverse Proxy

cat > /etc/nginx/sites-available/tipulog << 'EOF'
server {
    listen 80;
    server_name clinic.example.co.il;
    client_max_body_size 25m;   # העלאת מסמכים עד 20MB
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
EOF
ln -s /etc/nginx/sites-available/tipulog /etc/nginx/sites-enabled/
nginx -t && systemctl reload nginx

שלב 5 – HTTPS חינם עם Certbot

apt install -y certbot python3-certbot-nginx
certbot --nginx -d clinic.example.co.il

Certbot מגדיר HTTPS ומחדש את התעודה אוטומטית. מרגע זה המערכת זמינה ב-https://clinic.example.co.il.

שלב 6 – חומת אש

ufw allow OpenSSH
ufw allow 'Nginx Full'
ufw enable

עדכון גרסה בהמשך

cd /opt/tipulog
git pull
npm ci && npm run build
pm2 restart tipulog
גיבוי בשרת: אותו עיקרון כמו מקומית – גבו את /opt/tipulog/data (קובץ הנתונים והמסמכים). למשל cron יומי שמעתיק ל-S3 או למחשב אחר.

11. פריסה עם Docker

המאגר כולל Dockerfile ו-docker-compose.yml מוכנים. הנתונים נשמרים ב-Volume בשם tipulog-data, כך שעדכון גרסה לא מוחק כלום.

עם docker compose (מומלץ)

git clone https://github.com/effimorremitrix/tipulog-.git
cd tipulog-
SESSION_SECRET=$(node -e "console.log(require('crypto').randomBytes(32).toString('hex'))") \
  docker compose up -d --build

או ידנית

docker build -t tipulog .
docker run -d --name tipulog -p 3000:3000 \
  -v tipulog-data:/app/data \
  -e SESSION_SECRET=PASTE-A-LONG-RANDOM-STRING \
  --restart unless-stopped tipulog

מול האינטרנט העמידו Nginx/Caddy עם HTTPS כמו בפרק 10 (שלבים 4–6), או כל Load Balancer של ספק הענן.

עדכון גרסה

cd tipulog-
git pull
docker compose up -d --build

12. פריסה על Railway / Render (ללא שרת משלכם)

שתי הפלטפורמות בונות את האפליקציה ישירות מ-GitHub ותומכות בדיסק קבוע (Volume) – בדיוק מה שהמערכת צריכה. ההקמה כולה בדפדפן.

Railway

  1. היכנסו ל-railway.app עם חשבון GitHub ובחרו New Project → Deploy from GitHub repo ואת המאגר.
  2. Railway מזהה את ה-Dockerfile ובונה אוטומטית.
  3. ב-Settings → Volumes הוסיפו Volume עם Mount Path: /app/data (חובה! בלי זה הנתונים יימחקו בכל פריסה).
  4. ב-Variables הגדירו SESSION_SECRET (ואת משתני Twilio/S3 אם רלוונטי).
  5. ב-Settings → Networking צרו דומיין ציבורי או חברו דומיין משלכם.

Render

  1. ב-render.com בחרו New → Web Service וחברו את המאגר (זיהוי Docker אוטומטי).
  2. בחרו תוכנית עם Persistent Disk והגדירו Mount Path: /app/data.
  3. הגדירו SESSION_SECRET ב-Environment, וחברו דומיין ב-Custom Domains (HTTPS אוטומטי).
שימו לב: בתוכניות חינמיות השירות "נרדם" חוסר פעילות – תזכורות הוואטסאפ האוטומטיות לא יישלחו בזמן. לקליניקה אמיתית בחרו תוכנית בתשלום (החל מ-‎~5$), או הגדירו cron חיצוני שקורא ל-/api/reminders/run (פרק 13).

13. חיבור Twilio – בוט וואטסאפ נכנס ותזכורות יוצאות

פרק זה מחבר את המערכת לוואטסאפ אמיתי דרך Twilio, בשני כיוונים:

  • נכנס (Webhook): מטופלים שולחים הודעה למספר הקליניקה, והבוט קובע/מציג/מבטל תורים.
  • יוצא (תזכורות): המערכת שולחת תזכורת וואטסאפ לפני כל תור.

תנאי מקדים: המערכת פרוסה בכתובת HTTPS ציבורית (פרקים 10–12). לבדיקות מקומיות בלבד אפשר לחשוף את המחשב זמנית עם ngrok http 3000.

שלב 1 – חשבון Twilio ופרטי הגישה

  1. פתחו חשבון ב-twilio.com (חינם לניסוי, עם קרדיט התחלתי).
  2. ב-Console הראשי (Account Dashboard) העתיקו שני ערכים: Account SID (מתחיל ב-AC) ו-Auth Token. אלו המפתחות של החשבון – שמרו עליהם כמו על סיסמה.

שלב 2 – התחלה מהירה עם ה-Sandbox (מומלץ לבדיקה)

ה-Sandbox של Twilio מאפשר לבדוק את הכול עוד לפני אישור מספר עסקי:

  1. ב-Console נווטו אל: Messaging → Try it out → Send a WhatsApp message.
  2. יוצג מספר ה-Sandbox (בדרך כלל +1 415 523 8886) וקוד הצטרפות בסגנון join two-words.
  3. מכל טלפון שישתתף בבדיקה (למשל הטלפון של מטופל ניסיון), שלחו בוואטסאפ את הודעת ההצטרפות למספר הזה. ב-Sandbox רק מספרים שהצטרפו יכולים להתכתב.
  4. בלשונית Sandbox settings, בשדה "When a message comes in" הזינו: 
    https://your-domain/api/whatsapp/webhook
    עם Method: POST, ולחצו Save.

שלב 3 – משתני הסביבה במערכת

הוסיפו לשרת (קובץ .env ב-VPS, ‏Environment Variables ב-Render/Railway, או docker-compose.yml):

TWILIO_ACCOUNT_SID=ACxxxxxxxxxxxxxxxx
TWILIO_AUTH_TOKEN=xxxxxxxxxxxxxxxx
TWILIO_WHATSAPP_FROM=+14155238886      # מספר ה-Sandbox, או המספר העסקי שלכם
WHATSAPP_WEBHOOK_URL=https://your-domain/api/whatsapp/webhook
משתנהנכנס (בוט)יוצא (תזכורות)
TWILIO_AUTH_TOKENאימות חתימת הבקשות מ-Twilioנדרש לשליחה
TWILIO_ACCOUNT_SID–נדרש לשליחה
TWILIO_WHATSAPP_FROM–המספר שממנו נשלחות התזכורות
WHATSAPP_WEBHOOK_URLחובה מאחורי Proxy/Nginx – חייב להיות זהה בדיוק לכתובת שהוזנה ב-Twilio–

אחרי שינוי משתנים – הפעילו מחדש את השירות (pm2 restart tipulog / Redeploy).

שלב 4 – הגדרות בתוך המערכת

  1. היכנסו לעמוד וואטסאפ במערכת.
  2. סמנו "הפעלת קביעת תורים בוואטסאפ" והזינו במספר הקליניקה את אותו מספר מ-TWILIO_WHATSAPP_FROM (למשל +14155238886 ב-Sandbox).
  3. סמנו "הפעלת תזכורות אוטומטיות" וקבעו כמה שעות מראש לשלוח.
  4. ודאו שלמטופלי הבדיקה יש בתיק את מספר הטלפון הנכון – כך הבוט מזהה אותם.

שלב 5 – בדיקה

  1. נכנס: מהטלפון שהצטרף ל-Sandbox שלחו "שלום" למספר ה-Sandbox. אמור לחזור תפריט הבוט. השיבו 1 וקבעו תור – ובדקו שהוא הופיע ביומן עם הסימון "נקבע בוואטסאפ".
  2. יוצא: קבעו לאותו מטופל תור בטווח התזכורות ולחצו "⏰ שליחת תזכורות עכשיו". ביומן התזכורות בעמוד וואטסאפ הסטטוס צריך להיות נשלחה (ולא "סימולציה"), וההודעה להגיע לטלפון.

שלב 6 – מעבר לפרודקשן (מספר עסקי אמיתי)

ה-Sandbox מוגבל למספרים שהצטרפו ידנית ואינו מתאים למטופלים אמיתיים. לפרודקשן:

  1. ב-Twilio: ‏Messaging → Senders → WhatsApp senders → New sender. תידרש התחברות ל-Meta Business וקישור מספר טלפון (אפשר לרכוש מספר מ-Twilio). אישור ה-Sender לוקח בדרך כלל מספר ימים.
  2. לאחר האישור, הגדירו את ה-Webhook של ה-Sender (או של ה-Messaging Service שאליו הוא משויך) לאותה כתובת: https://your-domain/api/whatsapp/webhook.
  3. עדכנו את TWILIO_WHATSAPP_FROM למספר העסקי, ואת "מספר הוואטסאפ של הקליניקה" בעמוד ההגדרות.
חשוב – חלון 24 השעות של WhatsApp: וואטסאפ מתיר לעסק לשלוח הודעה חופשית רק בתוך 24 שעות מההודעה האחרונה של הלקוח. תזכורת שנשלחת מחוץ לחלון הזה חייבת להתבסס על תבנית מאושרת (Content Template). צרו ב-Twilio ‏(Messaging → Content Template Builder) תבנית תואמת לנוסח התזכורת שהגדרתם במערכת והגישו לאישור Meta. ב-Sandbox המגבלה רופפת יותר ולכן הבדיקות עוברות – אל תסיקו מזה שהכול יעבוד בפרודקשן בלי תבנית.

פתרון תקלות

תסמיןסיבה נפוצה ותיקון
הבוט לא עונה כלל‏Webhook לא נשמר ב-Twilio, כתובת שגויה, או שהשירות לא נגיש ב-HTTPS. בדקו ב-Twilio ‏Monitor → Logs → Errors.
שגיאת 403 Invalid signatureWHATSAPP_WEBHOOK_URL אינו זהה במדויק לכתובת שהוגדרה ב-Twilio (כולל https והנתיב). מאחורי Nginx/Proxy המשתנה הזה חובה.
"מספר הטלפון שלכם אינו מוכר"מספר הטלפון בתיק המטופל שונה מהמספר השולח. המערכת משווה לאחר נרמול (‎+972 ↔ 0), אך המספר חייב להיות קיים בתיק.
תזכורות נשארות בסטטוס "סימולציה"אחד משלושת משתני ה-Twilio חסר בשרת, או שהשירות לא הופעל מחדש אחרי הוספתם.
תזכורת בסטטוס "נכשלה" עם שגיאת 63016ההודעה נשלחה מחוץ לחלון 24 השעות ללא תבנית מאושרת – ראו האזהרה למעלה.
ההודעות מגיעות באיחור (Render/Railway)בתוכנית חינמית השירות נרדם. שדרגו תוכנית או הגדירו cron חיצוני ל-/api/reminders/run עם REMINDERS_CRON_SECRET.
